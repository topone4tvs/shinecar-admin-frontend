## 1. 角色与场景

| 角色 | 典型场景 | 设备 | 本期 |
|---|---|---|---|
| **超管（总部运维）** | 接电话处理现场问题：某工位门打不开、用户说余额不对、要退款、要查某车牌订单 | 手机，单手操作，常在店外 | ✅ 全功能 |
| 店长（未来） | 在店内巡场：看工位占用、开柜门、审核整洁照片 | 手机，店内弱网 | ⏳ 仅预留 |
| 加盟商（未来） | 同店长，但只能看自己门店 | 手机 | ⏳ 仅预留 |

**核心约束**：现场场景是「站着、单手、可能戴手套、网络一般」。
所以：主操作按钮不小于 88rpx 高、点击区不小于 88×88rpx、列表首屏尽量直出关键信息（车牌、时长、金额），不靠点进去看。

## 2. 作用域模型

系统里所有功能按三种作用域归类，**作用域决定切店是否影响它**。

| 作用域 | 包含 | 切店影响 | 数据来源 |
|---|---|---|---|
| **全局** | 整洁奖励审核、订单查询与详情、用户查询、用户资产操作 | 无影响，永远查全部门店 | 不带 `shop_id` |
| **门店** | 工位总览、门店工具（停车缴费） | 本页刷新；工具按新门店能力重算 | 显式带 `shop_id` |
| **工位** | 开门、语音、结束订单、维护、通风（毛巾柜预留） | 随门店变化；同店不同工位也可不同 | `station_id` + 其所属 `shop_id` |

### 2.1 切店规则（硬约束）

1. **切店入口只在「现场」页**，作为底部悬浮胶囊，不出现在顶部、不出现在二级页。
2. 切店后**只刷新现场页**（工位总览 + 门店工具）；查询 / 审核 / 我的不重算。
3. 工位详情进入即锁定 `shop_id`，页内不提供切店；返回现场才恢复切店能力。
4. 停车缴费从「门店工具 / 工位详情车牌行 / 订单详情」进入，**都显式带 `shop_id`**，不存在全局入口。
5. `currentShopId` 持久化到本地，冷启动优先恢复；若不在最新门店列表里（被移出 scope），回落到第一个门店并 toast 提示。

> 反例（不要这样做）：把切店放在顶部导航 → 用户在订单页切店后，会以为订单也筛了门店，实际是全局数据，容易误判。

## 3. 信息架构

```
Tabbar
├─ ① 现场（门店域）           ← 切店只影响这一页
│   ├─ 工位总览（状态汇总 + 2 列工位块）
│   ├─ 门店工具（能力驱动，本期：停车缴费）
│   └─ 工位详情（二级页，锁定 shop_id）
│        ├─ 基础操作：开门 / 语音播报 / 结束订单 / 设为维护
│        ├─ 扩展设备：通风全开（毛巾柜仅预留，本期不下发配置）
│        └─ 车牌行 → 停车缴费（带该车牌）
├─ ② 查询（全局域）
│   ├─ 订单：时间 / 手机 / 车牌 / 状态筛选 → 订单详情
│   └─ 用户：手机 / 车牌 → 用户详情（余额、券、车辆、流水、充值）
├─ ③ 审核（全局域）
│   └─ 整洁奖励：待审核 / 已通过 / 已拒绝
└─ ④ 我的（全局域）
    └─ 账号、角色、所属门店、版本、退出登录
```

**为什么「查询」把订单和用户放在一个 Tab**：两者是同一个检索动作的两个对象，
用户常常先搜手机号看人，再点进他的订单；放在两个 Tab 会来回切。
用顶部 `seg` 分段切换，保留彼此的检索词与滚动位置。

### 4.7 停车缴费

> 原则：**只缴不查**。停车系统只提供代缴接口（`car_no` 一参到底），没有「查待缴金额」能力，
> 所以页面不出现金额、不出现「刷新费用」，录入车牌 → 确认 → 代缴 → 结束。

| 功能 | 说明 | 旧实现 |
|---|---|---|
| 选门店 | 从入口带入（现场·门店工具 / 工位车牌行 / 订单详情），页内不切店；门店只用于**审计归属**，代缴参数与门店无关 | — |
| 录入车牌 | 车牌键盘；从工位 / 订单进入则预填，可直接代缴 | — |
| 代缴说明卡 | 固定三行：金额由停车系统结算（不展示）/ 门店账户代付 / 成功后自动抬杆 | — |
| 代缴 | 二次确认（标题带车牌）→ `POST /admin/v1/parking/pay` → 成功 toast「代缴成功，已放行」 | `/admin/order/pay-parking-fee` |
| 防重复 | 同一车牌 10 分钟内二次提交需再确认一次（`confirm_again=1`）；带 `order_id` 时若订单 `parking_paid_at` 非空直接拦截 | **新增** |
| 最近代缴 | 本门店近 7 天，取 `admin_operation_log`（车牌 + 时间 + 操作人，**无金额**） | 新增 |

**为什么不做金额**：三方接口返回 2xx 即视为已缴，不返回金额、流水号、入场信息。
界面若强行展示金额就得自己编，现场反而会拿它跟车主对账，错得更离谱。

## 6. 业务规则

### 6.1 工位状态口径

| 展示状态 | 判定 | 颜色语义 |
|---|---|---|
| 空闲 | `status = 2 已上线` 且 `work_status = 1` | 绿 |
| 使用中 | `status = 2 已上线` 且 `work_status = 2`（有真实订单） | 橙 |
| 清洁中 | `status = 2 已上线` 且 `work_status = 3`（管理员通电保养） | 橙（同占用色） |
| 维护中 | `status = 3`（优先级最高，忽略 work_status） | 品牌玫红 |
| 不展示 | `status = 1 建设中` / `status = 4 下线` | — |

- 三个汇总数必须与列表同口径：维护中优先计数；`work_status = 2 / 3` 都计入「使用中」；
  `status ∉ {2,3}` 不计入任何汇总。
- 工位号来自 `st_index`（补零字符串），展示前去前导零 → `001` 显示为「1 号」。
- **`work_status = 3 清洁中` 是管理员通电产生的占用**：没有订单，但对 C 端等价于不可用
  （`CheckShopStationValid` 里 `work_status != 1` 即拒）。断电后回到 1。
- **`power_state` 与 `work_status` 是两个维度**：`power_state` 只表示「指令已下发」，
  真正挡住用户的是 `work_status`。历史上只通电不改状态的做法已废弃。

### 6.2 自动代缴停车费（现有逻辑，本期不改规则）

仅在 `FinishOrder` 成功后异步触发（用户结束 / 超管强制结束）。三条 **OR** 短路：

1. 本单时长 > 50 分钟；
2. 同工位上一单结束 → 本单开单 < 5 分钟；
3. 同店其他在线工位全部「进行中或刚结束」。

> 已知缺陷：条件 ③ 依赖 `GetShopStationList` 回填的 `StationDetail.ID`，当前该字段恒为 0，
> 实际等效规则只有 ① ②。本期不修，但在后端方案 §8.3 标为可选修复项。
> 超时巡检不结束订单，所以超时单不触发代缴。

**与手动代缴的关系**：自动代缴成功即代表这笔车已放行，管理端再点「缴停车费」会造成重复扣款。
因此手动代缴前先看订单 `parking_paid_at`：非空则按钮改为「已代缴 10-18 11:26」，只能走「仍要再缴一次」二次确认。

### 6.3 整洁奖励

- 一条订单只能提交一条记录（`uk_order_id`）。
- 状态：`1 待审核 / 2 通过 / 3 拒绝`；只有待审核可操作。
- 通过 → 事务内加余额 + 写流水（`type=7 场地整理返现`）。
- **现有实现里返现失败不回滚审核状态**，只打日志 → 管理端必须能看出「已通过但没到账」，否则用户投诉无法定位。
- 拒绝必须写原因，用户在 C 端可看到。

### 6.4 结束订单 / 维护

| 操作 | 影响面（确认弹窗必须写清） |
|---|---|
| 结束订单 | 按当前时长立即结算并关单，C 端用户同步结束，不可撤回 |
| 设为维护 | 工位立即从 C 端下线，**进行中订单不受影响**，解除后恢复 |
| 通电 / 断电 | 设备停送电，**不产生订单也不计费**。通电后工位进入「清洁中」（`work_status=3`），C 端立即不可开单；有进行中订单或已被占用时不允许。断电即恢复空闲，不校验原状态 |
| 清空余额 | 余额归零 + 未使用的充值券作废，不可恢复 |
| 封禁 | 先清空余额再封禁（现有逻辑），C 端立即无法下单 |

## 7. 交互规则

### 7.1 危险操作分级

| 级别 | 表现 | 适用范围 |
|---|---|---|
| L1 普通 | 品牌色按钮，无需确认 | 复制、刷新、查看 |
| L2 需确认 | 品牌色确认弹窗，标题说明后果 | 开门、语音、通风全开、毛巾柜全开 |
| L3 破坏性 | **红色**确认按钮 + 影响面文案 + 不可撤回提示 | 结束订单、清空余额、封禁、退款 |
| L4 带输入 | 弹层内输入金额 / 原因后才可提交 | 赠送、扣减、拒绝审核 |

- L3 主按钮文案必须是**动词**（「确认结束」「确认清空」），不要用「确定」。
- 危险按钮不做长按，不做滑动，避免现场误触升级为误操作。

### 7.2 写操作通用规则

1. 点击即置 `loading` 并禁用，直到响应返回（防连点）。
2. 每次写操作带 `Idempotency-Key`（uuid），服务端 5 分钟内重复请求返回首次结果。
3. 成功：toast + **原地回填**（不整页刷新）；失败：toast 展示后端 `message`，保留页面状态。
4. 设备命令区分「已下发」与「已执行」：接口返回 `accepted` 时提示「已下发」，不承诺成功。
5. 任何写操作都要能被审计：`admin_operation_log` 记录操作人、门店、工位、能力、参数、结果。

### 7.3 刷新策略

| 场景 | 行为 |
|---|---|
| 现场页 `onShow` | 静默刷新汇总 + 工位列表（保留滚动位置） |
| 现场页下拉 | 显式刷新，顶部出现 loading |
| 切店 | 立即清空旧工位数据 → 显示骨架 → 拉新门店数据 |
| 工位详情 | 进入拉一次；`onShow` 拉一次；不轮询 |
| 查询列表 | 上拉加载更多，下拉刷新；筛选变更后回到顶部并清空游标 |
| 审核列表 | 审核成功后原地替换该条，不整页刷新 |

### 7.4 空态 / 加载 / 失败

每个列表必须有 4 态：`骨架屏`（首次）、`空态`（有图 + 一句引导）、`失败`（原因 + 重试按钮）、`有数据`。
空态文案要给**下一步动作**，不要只写「暂无数据」：

| 页面 | 空态文案 |
|---|---|
| 现场工位 | 该门店暂无已上线工位 · 联系总部确认工位配置 |
| 订单查询 | 没有匹配的订单 · 换个时间段或去掉车牌试试 |
| 用户查询 | 没有找到该用户 · 核对手机号或车牌是否完整 |
| 审核待办 | 待审核已清空 · 新的整洁照片会出现在这里 |

### 7.5 计时器

- 工位详情与现场的「已洗时长」都基于 `start_time` 与服务器时间差计算，**不做秒数累加**（防止息屏后漂移）。
- 全局只保留一个 `setInterval(1000)`，页面 `onHide` 清除、`onShow` 重建。
- 超过 24 小时显示 `25:03:41`（不转「1 天」），保证一眼看出异常长单。

### 7.6 多车牌

- 默认只显示「本单」车牌（开单时快照）+ 「共 N 个」入口。
- 展开后列出账户全部车牌，标注「本单 / 账户」，每条可复制、可缴停车费。
- 提示语固定：**「开单时只记录一个车牌，其余为账户下绑定的车辆；代缴停车费前请核对现场车辆。」**
  避免运维拿错车牌代缴。

### 7.7 车牌键盘（三处共用）

| 规则 | 说明 |
|---|---|
| 省份页 | 8 列 × 4 行（31 个省级简称，末位留空）；选中后自动切字母页 |
| 字母数字页 | 9 列；字符集 `A-Z` 去掉 `I`、`O`（避免与 1、0 混淆），数字 `0-9` |
| 第二字符 | 强制字母（省份后第一位必须是字母） |
| 长度 | 普通 7 位 / 新能源 8 位，可一键切换；切换时保留已输入 |
| 完成 | 未录满禁用；录满自动可点 |
| 最近车牌 | 展示最近 3 个，点击整串填入 |
| 输出格式 | 统一 `沪A·D2311`（中间用间隔号 `·`） |
| 校验 | 前端只校验结构；真伪由后端/停车系统判定 |

## 8. 文案规范

| 类别 | 规则 | 示例 |
|---|---|---|
| 金额 | `¥` + 两位小数，千分位；分与元在接口层转换，前端不拼算 | `¥1,280.00` |
| 时长 | `HH:mm:ss`；列表里可简写 `23 分 41 秒` | `01:02:10` |
| 时间 | 列表 `MM-DD HH:mm`；跨年带年份；详情 `yyyy-MM-dd HH:mm:ss` | `10-18 10:24` |
| 手机号 | 中间四位脱敏 | `138****8000` |
| 车牌 | 间隔号分隔，字母大写 | `沪A·D2311` |
| 订单号 | 列表不展示单号；详情展示 `#202610180324`，**不提供复制** | `#202610180324` |
| 状态词 | 固定词表，不用近义词 | 空闲 / 使用中 / 维护中；待审核 / 已通过 / 已拒绝；进行中 / 已完成 / 已取消 |
| 按钮 | 动词 + 对象，2–5 字；不使用「确定/提交」 | 开门、结束订单、确认清空 |
| 提示 | 说明「发生了什么 + 下一步」 | 设备离线，指令未下发 · 请检查工位网络后重试 |

## 9. 本期不做（明确边界）

- 「我的」里除账号与退出外的任何设置项（消息通知、门店管理、员工管理、关于我们详情）。
- 工位操作历史、设备在线时长统计、门店报表。
