# 04 · 前端技术方案

> 技术栈：Taro 4 + Vue 3 + TypeScript + Sass + Pinia（与现有 C 端一致，便于复用工具函数与构建经验）。
> 独立仓库，独立 appid，不复用 C 端代码仓库的页面与 store。

## 3. 状态管理

```ts
// stores/auth.ts
interface AuthState {
  token: string
  profile: AdminProfile | null   // { id, name, phone, role, role_text }
  shops: Shop[]
  boundAt: string
  status: 'idle' | 'loading' | 'ready'
}
```

| Store | 职责 | 持久化 |
|---|---|---|
| `auth` | token、当前账号、门店列表 | `token` 写 Storage（`admin_token`） |
| `shop` | `currentShopId`、`stations`、`summary`、`refreshedAt` | `currentShopId` 写 Storage |
| `capability` | `Map<"shopId:stationId", Capability[]>` | 不持久化（会话内缓存） |
| `app` | 环境、状态栏高度、安全区、待审数量 | 不持久化 |

**切换门店**：只调 `shop.loadStations(newId)`，不动 `auth`、不动 `capability` 的其他 key。
工位详情页在 `onLoad` 时把 `shopId` 固定进页面 state，不再读 store 的 `currentShopId`。

## 4. 请求层

```ts
// api/request.ts
type Options = {
  url: string
  method?: 'GET' | 'POST' | 'PATCH' | 'DELETE'
  data?: Record<string, any>
  auth?: boolean          // 默认 true
  idempotent?: boolean    // 写操作默认 true
  loadingText?: string
}
```

| 能力 | 实现 |
|---|---|
| 基址 | `process.env.TARO_APP_API`（dev/staging/prod 三套） |
| 鉴权 | 自动加 `Authorization: Bearer`；`auth:false` 时跳过 |
| 幂等 | `method !== 'GET'` 时自动生成 `Idempotency-Key`；**同一按钮重试复用**（见 `useIdempotency`） |
| 错误处理 | `code===0` 返回 `data`；否则抛 `ApiError{code,message,traceId}` |
| 401 / 40101 | 清 token → `Taro.reLaunch('/pages/login/index')`；40101 额外 toast「账号已在其他设备登录」 |
| 超时 | 15s；设备命令单独 8s |
| 重试 | 仅 GET，网络类错误重试 1 次（指数退避 300ms） |
| 日志 | 失败时 `console.error('[api]', url, code, traceId)`；生产只在 `__DEV__` 输出 |

**错误提示规约**：`request` 不自动 toast，由调用方决定（列表页内联展示，操作类 toast）。
统一封装 `withToast(promise, successText)`，避免每处重复写。

## 5. 启动与登录态

```
app.ts onLaunch
  ├─ 读 token
  │   ├─ 有 → GET /auth/profile
  │   │        ├─ 成功 → 写 auth store → reLaunch 现场
  │   │        └─ 401 → 清 token → reLaunch 登录
  │   └─ 无 → reLaunch 登录
  └─ 记录状态栏高度与安全区
```

```
登录页
  ① wxLogin()
      Taro.login() → code → POST /auth/wx-login
        ├─ need_bind=false → 存 token → 进现场
        └─ need_bind=true  → 存 ticket → 启用第 2 步
  ② bind()
      手机号 11 位 + 授权码 8 位 → POST /auth/bind
        ├─ 成功 → 存 token/profile/shops → 进现场
        └─ 失败 → toast「手机号或授权码不正确」+ 失败次数 >3 提示「如多次失败请联系总部」
```

**登录页交互细节**

- 第 1 步未完成时，第 2 步卡片 `pointer-events: none` + `opacity: .45`。
- 授权码输入：`@input` 转大写、去空格、过滤非字母数字、限 8 位。
- 手机号：纯数字、限 11 位，失焦时格式化为 `138 0013 8000`，提交前去掉空格。
- 键盘弹起时底部按钮不被遮挡（`adjust-position` + 滚动到可视区）。
- 登录按钮 loading 期间禁止重复提交。

## 6. 核心组件

### 6.1 PlateKeyboard

```ts
interface Props {
  visible: boolean
  modelValue: string          // 沪A·D2311
  recent?: string[]
  allowNewEnergy?: boolean    // 默认 true
}
interface Emits {
  'update:modelValue': [v: string]
  'confirm': [v: string]
  'update:visible': [v: boolean]
}
```

**内部状态机**

```
page: 'prov' | 'char'         // 当前键盘页
chars: string[]               // ['沪','A','D','2','3','1','1']，不含分隔点
len: 7 | 8                    // 普通 / 新能源
```

规则：

| 条件 | 行为 |
|---|---|
| `chars.length === 0` | 只能选省份；选完自动 `page='char'` |
| `chars.length === 1` | 只能输字母（第二字符强制字母），字母键可用、数字键置灰 |
| `chars.length >= len` | 所有键置灰，完成键高亮 |
| `len = 8` 且已输 8 位 | 完成键高亮；切回 7 位且已输 8 位 → 截断并 toast |
| 点删除 | 删末位；删到 0 位自动回省份页 |
| 点省份格 | 替换省份，保留后续字符 |
| 完成 | 拼为 `沪A·D2311`（第 1 位后插 `·`）emit |

**显示区格子**：`1 个省份格 + 1 个分隔点 + 6/7 个字符格`；未填格显示占位（浅底无字）。

**最近车牌**：从 Storage `recent_plates` 读，最多 3 个；确认后 unshift + 去重 + 截断 3。

**使用位置**：查询·订单车牌筛选、查询·用户车牌、停车缴费。三处都用同一个组件，不复制样式。

### 6.2 CapabilityAction

```ts
interface Props { capability: Capability; disabled?: boolean }
interface Emits { execute: [action: string, params: Record<string, any>] }
```

按 `render` 分派：

| render | 交互 | 产出 |
|---|---|---|
| `instant` | 点击直接 emit | `{}` |
| `confirm` | 弹 `ConfirmDialog`（`tone=danger` 用红色） | `{}` |
| `form` | 弹 `AppSheet` + 动态表单 | 表单值 |
| `toggle` | 按当前状态决定 action（`maintenance` 用 `set`/`clear`） | `{}` |
| `page` | `Taro.navigateTo(capability.page)` | — |
| 未知 | 降级为 `confirm` | `{}` |

**动态表单字段**

| type | 渲染 |
|---|---|
| `text` | 输入框，`maxlength` 由配置给 |
| `number` | 数字键盘，单位后缀 |
| `chips` | 预设话术/金额，单选或多选 |
| `grid` | `DoorGrid`（柜门），`multi` 决定单选/多选 |

**提交**：校验必填 → 生成/复用幂等键 → **按 `capability.route` 分派**：

| route | 提交到 |
|---|---|
| `device_command`（默认） | `POST /stations/{id}/commands` |
| `order_finish` | `POST /orders/{order.id}/finish` |
| `station_maintenance` | `POST /stations/{id}/maintenance`（按当前状态决定 `set`/`clear`） |

`device_command` 返回 `accepted` 则 toast「已下发」并关闭弹层；
业务接口返回成功后**原地回填**工位状态（不整页刷新）。

**多 action 的能力**：`form` 提交时用 `actions[0].action`；其余动作作为独立按钮（不走表单）并各自带 `confirm`。
本期没有这类配置（毛巾柜未 seed），逻辑先按此实现，等配置下发即可用。

### 6.4 ShopSwitcher

- 固定在现场页底部，tabbar 之上，渐变遮罩防内容穿透。
- 点击弹 `AppSheet`，列出 scope 内门店：门店名 + 工位总数 + 当前标记。
- 选择后：`shop.setCurrent(id)` → 页面显示骨架 → 重新拉 `stations` → 关闭弹层。
- 切换失败（网络）：保留旧门店数据 + toast，不进入空态。

### 6.5 useStationTimer

```ts
export function useStationTimer(startTime: Ref<string | null>) {
  const now = ref(Date.now())
  // 单例 interval：第一个使用者创建，最后一个销毁
  const text = computed(() => formatDuration((now.value - parse(startTime)) / 1000))
  return { text }
}
```

- 基于 `start_time` 与本地时钟差，不累加秒数。
- 服务端时间偏差：登录后调一次 `/health` 取 `Date` 头，算 `serverOffset`，用它校正 `now`。
- 页面 `onHide` 暂停（清 interval），`onShow` 立即 `now = Date.now()` 再启动。

### 6.6 AppSheet / ConfirmDialog / Toast

| 组件 | 要点 |
|---|---|
| `AppSheet` | `visible` 双向绑定；`max-height: 84%`；内容区滚动；遮罩点击关闭；`catchtouchmove` 防穿透 |
| `ConfirmDialog` | `title / content / confirmText / tone`；主按钮 loading；不允许两个弹层同时打开（用全局 `sheetStack` 计数） |
| `Toast` | 封装 `Taro.showToast({icon:'none'})` 不够可控 → 自研轻组件，支持 2 行文案 |

## 7. 页面实现要点

| 页面 | 关键数据 | 接口 | 注意 |
|---|---|---|---|
| 登录 | `step, ticket, phone, code` | `auth/wx-login`、`auth/bind` | 第 2 步禁用态；授权码格式化 |

| 查询 | `tab, filters, list, cursor` | `orders`、`users` | 切换订单/用户保留各自筛选；筛选变更重置 cursor |
| 订单详情 | `order` | `orders/{id}` | 底部按钮按 `actions.can_finish` 显示 |
| 用户详情 | `user, vehicles, logs, recharges` | `users/{id}/*` | 资产操作后局部刷新余额与流水 |

| 我的 | `profile, shops, version` | `auth/profile` | 退出二次确认；环境切换仅 `__DEV__` |

## 8. 性能

| 项 | 措施 |
|---|---|
| 首屏请求 | 现场页只 1 个聚合请求（`shops/{id}/stations`），不并发拉详情 |
| 避免 N+1 | 工位列表已带进行中订单，点进详情前可用列表数据预渲染骨架 |
| 图片 | 审核图缩略加 CDN 参数（`?imageView2/2/w/240`，若 CDN 支持）；点击才加载原图 |
| 长列表 | 游标分页，`onReachBottom` 追加；单页 20 条；不做虚拟列表（量级不需要） |
| 计时器 | 全站单例；仅现场与工位详情使用 |
| setData | 列表追加用 `concat` 生成新数组；避免整对象替换导致全量 diff |
| 包体 | 无 UI 库；图标本地 8 个小 png；`lazyCodeLoading: requiredComponents` |
| 缓存 | 门店列表、能力配置会话内缓存；`staleTime` 5 分钟，切店失效 |

## 11. 环境与发布

| 环境 | API | 用途 |
|---|---|---|
| dev | `https://dev-api.shinecar.club` | 本地联调 |
| staging | `https://staging-api.shinecar.club` | 体验版、验收 |
| prod | `https://api.shinecar.club` | 正式 |

- 构建：`npm run build:weapp -- --env=prod`，产物 `dist/`。
- 发布：微信开发者工具上传（CI 用 `miniprogram-ci`），版本号取 `package.json`。
- 回滚：微信后台「版本回退」到上一线上版本；后端接口保持向后兼容一个版本。
- 切环境必须清 token（不同环境账号体系隔离）。
