## 1. 里程碑

| 阶段 | 交付物 | 验收标准 | 依赖 |
|---|---|---|---|
| **P0 地基**<br/>登录 + 现场 | 建表与迁移、`admin_accounts` 建号脚本、`/auth/*`、`/shops`、`/shops/{id}/stations`；登录页、现场页、原生 tabBar | 真机可登录；能切换门店；工位状态与 C 端一致；断网有失败态 | 服务器域名（appid 已注册） |
| **P1 现场操作** | `/stations/{id}`、`/capabilities`、`/commands`、`/maintenance`；工位详情页、能力渲染器、语音弹层、确认弹层 | 开门 / 语音 / 结束订单 / 设维护 全部可用；设备离线有明确提示；重复点击不重复执行 | P0、MQTT 预发环境 |
| **P2 扩展设备 + 停车** | `admin_capabilities` seed（含 `ventilation`）、`/parking/pay` + `/parking/records`、`sc_orders.parking_paid_at`；通风按钮、停车缴费页 | 未配置能力不渲染；停车页不显示金额、录入车牌可直接代缴；重复代缴被拦 | P1、停车系统全局配置就绪 |
| **P3 查询** | `/orders`、`/orders/{id}`、`/orders/{id}/finish`、`/users*`；查询页（订单/用户分段）、订单详情、用户详情 | 跨店检索准确；车牌键盘三处复用；订单详情费用构成与后端一致 | `sc_orders.plate_no` 上线 |
| **P4 审核与资产** | `/cleanup-rewards*`、`/users/{id}/actions`、`/recharges/{id}/refund`、`/accounts*`；审核页、资产操作弹层 | 审核通过后余额与流水正确；返现失败可见可重试；资金操作有审计 | P3 |
| **P5 收尾** | 操作日志查询页、待审角标、环境切换、埋点与监控 | 关键路径有日志；提审通过 | P4 |

> 规模提示（S/M/L，非人日）：P0 `L`、P1 `M`、P2 `M`、P3 `L`、P4 `M`、P5 `S`。
> **毛巾柜不在任何阶段**：本期只预留命令通道（见后端 §7.1），协议确认后单独排一个小迭代，不动现有排期。

### 1.1 关键路径

```
建表/migration ──► 登录 ──► 现场 ──► 工位操作 ──► 查询 ──► 审核 ──► 提审
                              └──► 通风（能力配置）
停车系统全局配置 ──────────────► 停车代缴 ──┘
```

- **没有硬件强依赖**：通风沿用现有 `ventilation` target（代码里已验证），毛巾柜只留通道，不阻塞任何阶段。
- **停车**：现有 `config.Cfg.ParkingFee` 配好即可用；没有查询接口，所以不排「等接口」的时间。

## 3. 验收用例

### 3.1 登录

| # | 场景 | 步骤 | 预期 |
|---|---|---|---|
| A1 | 首次登录 | 微信授权 → 输手机号 + 授权码 | 进入现场页；授权码再用于其他微信登录失败 |
| A2 | 再次登录 | 杀进程重进 | 免授权码直接进；token 过期则静默换新 |
| A3 | 授权码错误 | 输错 1 次 | toast「手机号或授权码不正确」，不区分具体原因 |
| A4 | 连错 5 次 | 同一微信连错 5 次 | 锁 30 分钟，提示「操作过于频繁」 |
| A5 | 账号停用 | 后台停用后重进 | 「账号已停用，请联系总部」，不回现场页 |
| A6 | 重复绑定 | 同一个微信绑第二个手机号 | 被拒；需先解绑 |
| A7 | 退出登录 | 我的 → 退出 | 本地 token 清空；旧 token 立即失效 |

### 3.2 现场与切店

| # | 场景 | 预期 |
|---|---|---|
| B1 | 工位状态 | 与 C 端口径一致；维护中优先；建设中/下线不出现 |
| B2 | 汇总数 | 使用中 + 空闲 + 维护中 = 列表工位数 |
| B3 | 切店 | 只刷新现场；查询/审核数据不变 |
| B4 | 切到无工位门店 | 显示空态「该门店暂无已上线工位」 |
| B5 | 冷启动 | 恢复上次门店；门店被移除则回落第一个并 toast |
| B6 | 断网刷新 | 保留旧数据 + 顶部提示「网络异常，显示上次数据」 |

### 3.3 工位操作

| # | 场景 | 预期 |
|---|---|---|
| C1 | 开门（设备在线） | toast「已发送开门指令」；工位门状态在 3s 内变化（若固件回传） |
| C2 | 开门（设备离线） | 按钮不置灰；点击后提示「设备离线，指令未下发」，不假装成功 |
| C3 | 语音播报 | 预置与自定义都能下发；空文本禁用提交 |
| C4 | 结束订单 | 二次确认；成功后工位变空闲、订单状态变已完成；**用户端同步结束** |
| C5 | 结束订单（无进行中订单） | 提示「当前工位没有进行中的订单」 |
| C6 | 设维护 | 工位立即变维护中；C 端不可下单；进行中订单不受影响 |
| C7 | 解除维护 | 恢复为空闲（或使用中，取决于是否有单） |
| C8 | 重复点击开门 | 5 分钟内同幂等键只下发一次 |
| C9 | 能力未配置 | 扩展设备区块整体不显示，不留空白 |
| C10 | 计时卡无金额 | 只显示状态、已洗时长、门店、开始时间；**没有「已消费 / 预估费用」**；抓包确认 `/stations/{id}` 与 `/shops/{id}/stations` 都不返回金额字段 |

### 3.4 通风（毛巾柜本期不验）

| # | 场景 | 预期 |
|---|---|---|
| D1 | 通风 | 下发 `ha_control / ventilation / turn_on`；提示「5 分钟后自动关闭」（以设备为准） |
| D2 | 未配置门店 | 「扩展设备」区块整体不显示，不留空白与标题 |
| D3 | 毛巾柜未 seed | 工位详情看不到毛巾柜任何按钮；`POST /commands` 传 `towel_cabinet` 返回「能力不存在」 |
| D4 | 预留能力上线演练 | 手工 seed 一条 `towel_cabinet` 配置 → 刷新页面即出现按钮（验证「不发版」这条承诺） |

### 3.5 查询

| # | 场景 | 预期 |
|---|---|---|
| E1 | 按手机号查订单 | 结果只含该用户；跨门店都出现 |
| E2 | 按车牌查订单（新单） | 命中 `plate_no` 快照 |
| E3 | 按车牌查订单（历史单） | 走用户车牌兜底，结果不缺 |
| E4 | 时间边界 | 起止时间包含端点；跨天正确 |
| E5 | 分页 | 上拉追加不重复、不丢；到底显示「没有更多」 |
| E6 | 订单详情 | 费率构成相加 = 实付；券抵扣、夜间优惠、新人优惠分项正确 |
| E7 | 按车牌查用户 | 命中多账户时全部列出 |
| E8 | 车牌键盘 | 省份页 8 列；第二字符只能字母；7/8 位切换；未满禁用完成 |
| E9 | 不复制单号 | 列表与详情均无复制入口 |

### 3.6 审核与资产

| # | 场景 | 预期 |
|---|---|---|
| F1 | 通过审核 | 状态变已通过；用户余额增加；流水类型「场地整理返现」 |
| F2 | 拒绝审核 | 原因必填；C 端可见原因 |
| F3 | 重复审核 | 提示「该记录已审核过」 |
| F4 | 返现失败 | `reward_status=2`，列表标红「返现失败」；点重试可补发 |
| F5 | 赠送余额 | 金额 >0；流水类型「赠送」；余额与流水一致 |
| F6 | 扣减 | 超过余额时拒绝并提示 |
| F7 | 清空 | 余额归零 + 未使用充值券作废；不可撤回 |
| F8 | 封禁 | 先清余额再封禁；C 端立即不能下单 |
| F9 | 退款 | 金额不超过原充值；状态回写；有审计 |

### 3.7 停车

| # | 场景 | 预期 |
|---|---|---|
| G1 | 页面形态 | 只有车牌 + 代缴说明卡 + 最近代缴；**没有金额、没有「刷新费用」** |
| G2 | 未录车牌 | 代缴按钮 `opacity .45` 且不可点，点击只 toast「请先录入车牌」 |

| G7 | 从工位进入 | 车牌预填为「本单车牌」，也可改成账户下其他车牌（现场核对后改） |

## 5. 风险与对策

| # | 风险 | 影响 | 对策 |
|---|---|---|---|
| 1 | **审核被拒**（自建登录 + 手机号手输） | 上线延期 | 提审填测试账号 + 备注说明；准备 1 分钟操作录屏备用 |
| 2 | **毛巾柜协议未定** | 无影响（已移出本期） | 只留命令透传通道；协议确认后 seed 一条配置即上线，不占排期 |
| 3 | 停车系统无查询接口 | 页面无法显示金额 | 本期就是「不显示金额」的版本，不是降级；三方将来若有查询再补 |
| 4 | 自动代缴条件③失效 | 可能多代缴/少代缴 | 本期不改规则；新增 `parking_paid_at` 至少能在手动代缴时拦住重复 |
| 5 | 返现失败无感知 | 用户投诉无据可查 | 新增 `reward_status` + 列表标红 + 重试接口 |
| 6 | 历史订单车牌为空 | 车牌查不到老单 | `plate_no` 快照 + 用户车牌兜底；上线时告知运营「新单才准」 |
| 7 | 设备离线当成功 | 现场反复点 | 接口区分 `accepted` 与执行结果；文案「已下发」不承诺成功 |
| 8 | token 失效策略太狠 | 误踢正常用户 | `token_version` 只在退出/停用/改角色/解绑时 +1；登录成功不 +1（否则多设备互踢） |
| 9 | 大表加索引锁表 | 下单受影响 | 低峰执行；先 `pt-online-schema-change` 或 `INPLACE` 验证 |
| 10 | 仓库/CI 未就绪 | 前端排期延后 | 独立 repo 第一天建好，CI 用 `miniprogram-ci` |

## 6. 后续扩展路线

| 优先级 | 项 | 改动面 |
|---|---|---|
| 高 | **店长角色** | 建 `role=1` 账号 + 写 `admin_shop_scopes` + 打开 `RequireRole/RequireShopScope`；前端「我的」显示所属门店，现场只列 scope 内门店 |
