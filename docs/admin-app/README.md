# 焕车掌柜 · 管理端小程序｜方案总览

> 版本 **v1.2** ｜ 2026-10-20 ｜ 对应可点原型 `../admin-app-ui-demo.html`
> 适用：独立管理端小程序（现场运维 / 跨店查询 / 整洁审核 / 停车代缴）
> 不含：营销活动、计费规则、券码规则、C 端下单与充值流程

---

## 1. 一句话结论

**人不通、数据通、接口重包一层。**

新建一个独立 appid 的管理端小程序，用独立的 `admin_accounts` 管理员体系登录（微信只作设备身份），
所有对外接口走新的 `/admin/v1` 命名空间（复用 service，不复用 C 端 DTO），
界面按「全局 / 门店 / 工位」三种作用域排布，设备按钮由**能力配置**下发。

## 3. 本期范围

### 3.1 做

1. **两步登录**：微信授权 → 手机号 + 8 位授权码，绑定后免授权码进入。
2. **现场**：门店工位总览（状态、计时、尾号）、底部悬浮切店、门店工具（停车缴费）。
3. **工位详情**：状态计时卡、当前用户（手机 / 多车牌 / 余额 / 券）、基础操作 4 个、扩展设备（本期仅**通风全开**；毛巾柜只预留后端命令通道与 UI 草案）。
4. **查询**：订单（时间 / 手机 / 车牌 / 门店）、订单详情、用户（手机 / 车牌）、余额流水、充值记录。
5. **审核**：整洁奖励待办 / 历史，通过或拒绝（拒绝必填原因）。
6. **停车代缴**：录入车牌 → 二次确认 → **直接代缴**，沿用现有停车逻辑；不查询费用、不展示金额。
7. **我的**：账号与角色、所属门店、版本、退出登录（其余功能本期不做）。
8. **后端**：`/admin/v1` 全套接口、管理员账号表、能力配置表、操作日志。

### 3.2 不做

- 所有营销相关内容：首页营销弹窗、新人优惠、充值档位、券码售卖规则、计费规则展示。
- C 端下单、充值、开票、发票、会员等级。
- 工位「关门」「上电」：管理端没有对应场景（底层指令保留，界面不暴露）。
- **毛巾柜的界面与能力配置**：本期只在命令层预留 `towel_cabinet` 的 `target/action` 透传，待固件协议确认后再 seed 一条配置即可上线，前端不发版。
- **停车费金额查询**：三方停车系统只提供「代缴」，不提供「查待缴」，因此页面不做金额卡、不做刷新费用。
- **进行中订单的金额**：不做「已消费 / 预估费用」试算，工位详情与现场页都不显示（现有 `CalculateFee` 带写副作用，且现场看时长就够）。
- 操作日志展示页（本期只写库）、数据报表、多语言、深色模式。
- 店长差异化权限（表结构与代码预留，本期只用超管）。

## 4. 关键决策

| # | 决策 | 结论 | 理由 |
|---|---|---|---|
| 1 | 形态 | 独立小程序、独立 appid（**已注册完成**）、独立 repo | 与 C 端发布节奏解耦，包体小、审核独立 |
| 2 | 身份 | 独立 `admin_accounts`，不打通 C 端账号 | 管理员不该依赖 C 端注册流程；微信只作设备身份 |
| 3 | 登录 | 两步；授权码只存哈希、首绑失效 | 后台预建账号，最小可行且可回收 |
| 4 | 接口 | 新 `/admin/v1`，复用 service | C 端 DTO 夹带营销字段，改动会把管理端带崩 |
| 5 | 权限 | 三段式预留（角色 / 门店范围 / 能力 permission），**本期恒放行** | 只建超管，但未来加店长不用改接口 |
| 6 | 设备 | 能力配置驱动，统一 `POST /stations/{id}/commands`；本期只启用通风，毛巾柜只留命令通道 | 门店设备差异大，不能硬编码按钮；毛巾柜协议未定，先不接 UI |
| 7 | 指令范围 | 只暴露 开门 / 语音 / 结束订单 / 维护 | 关门、上电无管理场景 |
| 8 | 切店 | 只在「现场」页，底部悬浮胶囊；工位详情锁死 shop_id | 避免切店后跨店页看到串店数据 |
| 9 | 停车费 | **沿用现有全局配置 `config.Cfg.ParkingFee`**，只做「按车牌直接代缴」；不建门店配置表、不做金额查询 | 现有逻辑够用；停车系统只提供代缴接口，做金额卡等于画假数据 |
| 10 | 车牌 | 统一 `PlateKeyboard` 组件，三处复用 | 手输易错，且新能源 8 位需要区分 |
| 11 | 单位 | 设计稿 375pt，代码 750rpx（1px = 2rpx） | 与现有 C 端一致 |
| 12 | 主题 | 沿用品牌玫红 `#E6436E`，不做深色模式 | 与 C 端视觉连续 |

## 5. 角色与权限

### 5.1 三段式模型（预留）

```
身份  admin_accounts.status = 1
  └─ 角色  role: 2 超管 / 1 店长
       └─ 范围  admin_shop_scopes（超管不写 = 全部门店）
            └─ 能力  admin_capabilities.permission（any / super）
```

### 5.2 本期实际执行

| 项 | 本期行为 |
|---|---|
| 建号 | **只建 `role = 2`（超管）**，不写门店范围 → 全部门店 |
| 接口鉴权 | 只校验 token 有效 + 账号 `status = 1` + `token_version` 一致 |
| 门店范围 | 不校验（超管天然全量） |
| 能力 `permission` | 字段照常下发，前端不据此隐藏；后端 `RequirePermission` 保留但恒通过 |
| 数据表现 | `role`、`admin_shop_scopes`、`permission` 全部落库并参与 DTO，只是不参与拦截 |

> 目的：未来开加盟商时，只需「建 role=1 的账号 + 写 scope + 把 `RequirePermission` 打开」，
> 不需要改接口签名、不需要改表、前端也不需要改（按钮本来按能力列表渲染）。

### 5.3 未来打开时的三步

1. `POST /admin/v1/accounts` 允许 `role=1` 并写 `admin_shop_scopes`。
2. `middleware.AdminAuth` 后挂 `RequireRole` / `RequireShopScope`，能力接口按 `permission` 过滤。
3. 前端「我的」展示所属门店，「现场」只列 scope 内门店；切店入口自动生效（代码已按列表渲染）。

## 6. 已定稿事项

> 本轮已无待确认项：以下 5 条业务口径 + 10 条实现口径**全部确认执行**，可直接开工。

### 6.1 业务口径

| # | 事项 | 结论 |
|---|---|---|
| 1 | **停车缴费** | 沿用现有 `parkingfee.PayParkingFeeByConfig`：录入车牌 → 二次确认 → 直接代缴。**不查金额、不建门店配置表、不做代缴流水表**；审计写 `admin_operation_log`，订单只回写 `parking_paid_at` 用于防重 |
| 2 | **毛巾柜** | 只在命令层预留 `towel_cabinet` 的 `target/action` 透传；本期**不 seed 能力、不做界面、不做柜门网格**，等固件协议确认后 seed 一条配置即可上线，前端不发版 |
| 3 | **小程序 appid** | 已注册完成。只需把 appid 填进 `project.config.json`（具体值待提供） |
| 4 | **权限** | 本期只建超管，全功能开放；角色 / 门店范围 / 能力 permission 三段式落库但**不参与拦截** |
| 5 | **进行中订单的费用** | **不显示、不试算、不实现**。工位详情与现场页只展示「洗了多久 / 谁在洗 / 哪个工位」，费用以结束订单时的结算结果为准 |

> 关于第 5 条：现有 `ProcessOrderBilling` / `CalculateFee` 内部会 `markUserUsedFreeToday`（消耗用户当日免费机会）并核销券，
> 是**写操作**。既然不需要这个数字，就不必新写只读计费副本——直接不做，也顺手排掉了「看一次详情扣一次权益」的风险。

### 6.2 实现口径（已确认）

| # | 事项 | 确认结论 |
|---|---|---|
| a | 管理员账号初始化 | Go CLI `cmd/adminctl`：`--phone` 生成 8 位授权码（bcrypt 入库），人工线下发给管理员；首发不做后台建号页 |
| b | 授权码有效期 | **一次性**（首绑即失效）+ 未绑定 7 天过期；超管可重置，重置后旧码立即作废 |
| c | token 过期处理 | 7 天有效；401 时自动 `wx.login` 静默续期并**重放一次**请求，仍失败才回登录页 |
| d | 订单车牌快照 | `sc_orders` 加 `plate_no`，开单时写入；历史单用「用户当前绑定车牌」兜底检索 |
| e | 能力 `icon` | 存枚举 key（`door` / `voice` / `stop` / `wrench` / `fan` / `cabinet` / `park` / `coin`），前端映射图标，不存中文单字 |
| f | 审核待办角标 | tabbar「审核」显示数字，`onShow` 刷新，>99 显示 `99+` |
| g | 整洁奖励「已通过未到账」 | **本期做**：加 `reward_status`（0 待处理 / 1 已到账 / 2 返现失败），列表标红 + 「重新返现」按钮 |
| h | 代码仓库 | 前端独立 repo `shinecar-admin`；后端仍在 `shinecar-backend` 内加 `internal/api/adminv1` 包 |
| i | 是否展示建设中 / 下线工位 | 不展示（与 C 端口径一致），接口留 `include_offline=1`；色板已预留 |
| j | 能力配置首发方式 | SQL seed 脚本 + 只读接口；后台配置页排到 P5 之后（本期不做） |

### 6.3 开工前置（4 项，缺一项就会卡住）

| # | 需要什么 | 谁提供 | 卡在哪 |
|---|---|---|---|
| 1 | **小程序 appid** | 你 | 没有它无法真机预览、无法上传体验版；填 `project.config.json` |
| 2 | **服务器域名**（HTTPS + 备案） | 运维 | `request` 合法域名 `https://api.shinecar.club`、`downloadFile` 合法域名 `https://res.shinecar.club`；未配只能在开发者工具勾「不校验域名」，真机直接失败 |
| 3 | **超管手机号 + 姓名** | 你 | 建号 CLI（`cmd/adminctl`）的唯一输入；没有账号整条登录链路验证不了 |
| 4 | **停车 API 参数** | 运维 | `url` / `method` / `headers` / `form_params`；未配时停车页明确提示「停车费 API 未配置」，不假装成功 |
